# Project Rules

Правила, которым агент обязан следовать во всех фазах.
Добавляйте сюда условия, которые должны соблюдаться всегда — они будут прочитаны
перед началом каждой фазы и учтены при декомпозиции и реализации.

## Обязательные правила

- Всегда использовать английский язык для имён переменных, функций, классов и комментариев в коде
- Всегда запускать тесты (`.\scripts\test.ps1`) перед завершением задачи
- Следовать существующим конвенциям кода в проекте
- Все модули принимают `[string]$action` с `[ValidateSet(...)]`

## Правила слияния (актуально с 2026-10-17)

- **Два движка симлинков намеренно сосуществуют.** `src/modules/common/State.ps1` (winos) и `src/modules/plugins/common/State.ps1` — разные файлы, НЕ сливать без явной команды владельца. Причина: они обслуживают разные домены (конфиги vs плагины) и грузятся через dot-source, где 8 одинаковых имён функций попали бы в один scope
- **`S:\Plugins` — только чтение.** Инструмент никогда не пишет в библиотеку плагинов
- **Изменения в `S:\Git\powerlinks` во время слияния не делать** — он источник для W1, коммит `9c1f8a3`
- **W7 (объединение State.ps1) не выполнять без явной команды владельца** — единственный шаг с настоящим риском. Построчный diff уже сделан, см. задачу
- **W8 (линтерная политика) не выполнять без явной команды владельца** — это изменение стандартов проекта
- **Не путать механизм и назначение:** symlink-manager линкует ФАЙЛЫ конфигов, plugin-manager линкует КАТАЛОГИ плагинов

## Запреты по файловым операциям

- **`rm -rf` по каталогу, который агент не создавал, запрещён.** Правило добавлено
  после реальной потери: агент создал в `.temp/` две пробы, затем выполнил
  `rm -rf .temp` — и вместе с ними снёс четыре чужих файла незавершённой работы,
  которые даже не открывал. `.temp/` в `.gitignore`, поэтому восстановление через
  git было невозможно.
- **Удалять только те файлы, которые агент сам создал, и только по точному пути.**
  Если нужно убрать хвост своей работы — перечислять файлы явно, а не каталог.
- **Перед удалением каталога перечислить его содержимое** и убедиться, что там
  нет ничего, кроме созданного за эту сессию.
- **Перед `Remove-Item`/`rmdir` на путях вне репозитория** (особенно в системных
  папках и дисковых корнях) — сначала показать пользователю, что именно удаляется.
  Это тот же класс дефекта, что у вендорских `.bat` с `rd /q` по предположению,
  будто там лежит только их файл.

## Запреты

- Не изменять CI/CD конфигурацию без явного разрешения
- Не удалять существующие файлы (только в рамках явной задачи)
- Не коммитить в main/master без PR
- Не добавлять проверку администратора (проект работает без elevation)

## Конвенции проекта

- Имена функций: approved verbs (`Set-`, `Remove-`, `Update-`, `Get-`, `Invoke-`, `Read-`, `Show-`)
- Имена переменных: PascalCase для модулей/scope, lowerCamelCase для JSON-полей
- Точка входа: `main.ps1` (CLI + интерактив)
- Скрипты: `scripts/lint.ps1`, `scripts/test.ps1`
- Тесты: `tests/`, smoke-тесты с Pester 5.x+
- Конфиг: `data/data.json` (version 2, схема: `{ version, persistRoot, symlinks[] }`)
- **Source-of-truth root: `~/Storage/persist/`** (`$persist` в `vars.ps1`)
- Каждый `symlinks[].from` должен быть под `$persist` (исключения: `deploy-folder` → `$root`)
- Линтер-конфиг: `.pspsscriptanalyzer.psd1`

## Структура проекта

```
winos/
  main.ps1                       # CLI + интерактив (Back/Exit)
  src/
    init.ps1                     # bootstrap
    vars.ps1                     # модули, пути
    modules/
      symlink-manager.ps1        # глаголы: plan, apply, snapshot
      essentials.ps1             # install/uninstall (cursor themes)
      opencode-serve.ps1         # setup/remove/status/start/stop
      plugin-manager.ps1         # глаголы: plan, apply, revert, snapshot, status, adopt, verify
      common/
        State.ps1                # симлинки конфигов (winos)
      methods/
        symlink.ps1              # Set-Symlink, Remove-ItemLogged
        isolate.ps1              # per-app скрипты из data/isolate/
  manifests/                     # 28 штук (из powerlinks), по одной на папку плагина
  state/powerlinks.json          # allowlist плагинов (из powerlinks)
  scripts/
    lint.ps1                     # Invoke-ScriptAnalyzer
    test.ps1                     # Invoke-Pester
  tests/
    {module}.Tests.ps1
    modules/
      {module}.Tests.ps1
  data/
    data.json                    # version 2, symlinks[] (winos, конфиги)
    isolate/                     # per-app скрипты
    autorun/                     # .lnk для автозапуска
  bucket/                        # Scoop-манифесты
  .pspsscriptanalyzer.psd1       # конфиг линтинга
```

## Команды

- Запуск приложения: `.\main.ps1` (интерактив) или `.\main.ps1 "Module" action` (CLI)
- Запуск тестов: `.\scripts\test.ps1`
- Запуск линтера: `.\scripts\lint.ps1`
